# Расширенный формат описания источника

Программа задачи 1.1 принимает описание источника в формате JSON. Поддерживаются исходный формат без поля `type` и два расширенных типа: `markov` и `mixture`. Все вероятности задаются **строками** (`"1/3"`, `"0.25"`, `"1"`) и обрабатываются как точные рациональные числа (`Fraction`). Распределения должны быть непустыми, неотрицательными и нормированными; некорректные ссылки, типы данных и контексты отклоняются.

## 1. Исходный формат (периодический источник)

При отсутствии `type` используются поля:

- `models` — словарь «имя модели → распределение символов»;
- `switches` — словарь «имя переключателя → распределение имён моделей»;
- `source` — непустой список имён переключателей.

На позиции `i` (нумерация с нуля) действует переключатель `source[i % L]`, где `L = len(source)`. Он выбирает модель, а модель — символ. Выборы на разных тактах независимы. Исходные файлы читаются **без конвертации**. Пример: `tests/legacy_example.json`; вариант с `k=3`, `M=4`, `L=4`: `tests/variant11_legacy.json`.

## 2. Марковский источник (`"type": "markov"`)

Обязательные поля: `type`, `alphabet`, `depth`, `initial`, `models`, `switches`, `source`.

- `alphabet` — непустой список различных строк, образующих алфавит мощности `k`.
- `depth` — положительное целое число `d`, глубина памяти.
- `initial` — непустой список записей вида `{"context":["0","1","2"],"probability":"1/3"}`. Он задаёт **совместное распределение первых `d` символов**. Длина каждого контекста равна `d`; сумма вероятностей начальных контекстов равна единице.
- `models` — словарь «имя модели → непустой список переходов». Переход имеет вид `{"context":["0","1","2"],"distribution":{"0":"1/2","1":"1/2"}}` и задаёт распределение следующего символа при данном контексте. Контексты внутри одной модели не повторяются; в распределениях используются только символы из `alphabet`.
- `switches` и `source` устроены как в исходном формате. После первых `d` символов на позиции `i` применяется переключатель `source[i % L]`.

Для контекста `c` итоговое распределение символа `a` получается смешиванием распределений моделей текущего переключателя:

$$
P_i(a\mid c)=\sum_m P(m\mid \mathrm{switch}_i)\,P(a\mid c,m).
$$

После появления символа `a` контекст `(x₁,…,x_d)` заменяется на `(x₂,…,x_d,a)`. Описывать все `k^d` контекстов необязательно: переходы необходимы для каждого **достижимого** контекста и каждой достижимой фазы у всех моделей с положительным весом. Полный рабочий пример для `k=3`, `d=3`, `M=4`, `L=4`: `tests/markov_example.json`.

## 3. Смесь источников (`"type": "mixture"`)

Поле `components` — непустой словарь именованных компонент. Для каждой компоненты обязательны:

- `weight` — строка с вероятностью выбора компоненты;
- `source` — вложенный JSON-объект с описанием источника по любому из поддерживаемых правил (в том числе другой смеси).

Сумма `weight` по всем компонентам равна единице. Все компоненты обязаны иметь **одинаковый период `L`**. Допускается вложение смесей с ограниченной глубиной.

**Семантика:** при создании одной реализации случайно выбирается **одна компонента**, затем именно она генерирует всю последовательность. Компонента не перевыбирается на каждом такте. Для блока `B`, начинающегося с позиции `j`, вероятность равна

$$
P_j(B)=\sum_m w_m P_{m,j}(B),
$$

где `w_m` — вес компоненты. Полный пример: `tests/nonergodic_example.json` (с равными вероятностями выбираются последовательности, состоящие только из нулей или только из единиц). Это пример стационарного неэргодического источника; обоснование свойств приведено отдельно в отчёте.

## 4. Режимы программы

Оба режима доступны для всех трёх типов источников:

- `generate` — генерация `N > 0` символов; при отсутствии положительного `N` выдача продолжается до `Ctrl+C`;
- `analyze` — точная вероятность указанного блока с первой позиции, точное среднее по первым `L` начальным позициям, эмпирическая частота перекрывающихся вхождений в реализации длины `N` и таблица для `N = 10², 10³, 10⁴, 10⁵, 10⁶`.

Для анализа среднего используется

$$
\overline P(B)=\frac{1}{L}\sum_{j=0}^{L-1}P_j(B).
$$

Параметр `--seed` задаёт воспроизводимое состояние генератора случайных чисел.
